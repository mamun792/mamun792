## 🏗️ Architecture & Design Expertise

```
┌─────────────────────────────────────────────────────────────┐
│                   Clean / Onion Architecture                │
├─────────────┬──────────────┬───────────────┬───────────────┤
│  Presentation│ Application  │ Infrastructure│    Domain     │
│  Controllers │  Services    │  Repositories │  Entities     │
│  Resources   │  Commands    │  Cache (Redis)│  Value Objects│
│  Requests    │  Queries     │  External APIs│  Domain Events│
│  DTOs        │  Handlers    │  ORM / DB     │  Aggregates   │
└─────────────┴──────────────┴───────────────┴───────────────┘
```

| Pattern / Principle | Application |
|---|---|
| 🏛️ **Clean Architecture** | Strict layer separation — Domain, Application, Infrastructure, Presentation |
| 🧩 **DDD** | Aggregates, Value Objects, Domain Events, Bounded Contexts |
| ↔️ **CQRS** | Read/Write model separation — Commands vs Queries via dedicated handlers |
| 📦 **Repository Pattern** | Abstracted data access — swappable implementations, testable |
| ⚡ **Redis Caching** | Cache-Aside with mutex lock, Write-Through, TTL invalidation strategies |
| 🔐 **Security First** | JWT (access + refresh), RBAC/ABAC, httpOnly cookies, CSP, input validation |
| 🔁 **Idempotency** | Mandatory on all payment, settlement, and critical write operations |
| 🧪 **Test Behavior** | Unit + integration tests — test what the system does, not how |

## 🌟 Production Projects at Auxtech Limited

### 🟢 SASA — Multi-Tenant SaaS ERP Platform
> `Laravel 11` · `Multi-Tenant` · `DDD` · `CQRS` · `Redis` · `Docker` · `ProxySQL`

A fully operational **multi-tenant SaaS ERP** serving multiple business clients under strict tenant isolation. Backend lead for architecture and core modules.

**Key Technical Achievements:**
- ✅ Multi-tenant architecture using `stancl/tenancy` — row-level security + Global Scope tenant isolation
- ✅ CQRS + Domain Events for global configuration system — clean command/query separation
- ✅ Cache-Aside pattern with **mutex lock** to prevent cache stampede under high concurrency
- ✅ 7-phase Docker production topology: Nginx → App → Redis → MySQL + ProxySQL read-replica routing
- ✅ Full Clean Architecture layer separation — no business logic leaking into controllers
- ✅ Outbox Pattern for reliable Domain Event publishing across tenant boundaries

🔗 [Backend Repository](https://github.com/AuxtechbdDev/sasa_bk_end)

**Key Technical Achievements:**

## 📐 Architecture Philosophy

```
Request → Controller → FormRequest (Validation)
              ↓
          Service Layer (Business Logic)
              ↓
        Repository (Data Access)
              ↓
          Domain / Model
              ↓
         DTO → API Resource → Response
```

| Principle | Practice |
|---|---|
| 🔐 **Security First** | JWT, RBAC/ABAC, httpOnly cookies, CSP, rate limiting on every endpoint |
| 🧱 **Clean Architecture** | Strict layer separation — no logic leaking into controllers or models |
| ⚡ **Performance** | EXPLAIN-driven indexing, Redis Cache-Aside with mutex, keyset pagination |
| 🔁 **Idempotency** | Mandatory for payments, settlements, and all critical write operations |
| 🧪 **Test Behavior** | Test what the system does, not implementation details |
| 🔄 **CQRS** | Read/Write separation — dedicated command handlers and query handlers |
| 📦 **Small PRs** | Focused, reviewable, fast-to-merge — feature branch workflow |
| 🛡️ **Outbox Pattern** | Reliable event publishing — no lost domain events under failure |
